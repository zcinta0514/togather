## 一、先修 Bug：时间网格重做 ✅ 已完成

**结果：320px 下格子从 13.8px 变成 32.0px，标签重叠从 16 处降到 0。**

改法：每天一列、一周一行（按天每列 1 格，按半天每列 2 格），
日期标签从「格子顶上」移到「列顶」，跨月时标出月份。

实施中还抓到一个**几何检测抓不到**的 bug：半天粒度下最后一周只有 3 天时，
CSS Grid 自动排布会把下一组的元素填进同一行的空位，「早」标签于是跑进了日期那一行。
修法是每行末尾补齐空格子 —— **只有真的把页面看一眼才会发现。**

### 实测数据（320px 屏幕 / 30 天活动）

| 指标 | 实测值 | 问题 |
|---|---|---|
| 格子尺寸 | 13.8 × 13.8 px | **远低于 44px 触控下限** |
| 折行数 | 3 行 | |
| 压在其它格子上的日期标签 | 16 个 | 折行后标签压住上一行 |
| 横向重叠的标签 | 2 对 | 标签比格子宽 |

**根因：列数写死 14 是错的。**

```ts
const columns = Math.min(slotCount, 14);   // ← 问题在这
```

14 列在 320px 上每列只剩 14px。而且折行之后，每个格子的日期标签是
绝对定位在格子上方（`-top-4`）的，第二行开始就正好压在上一行的格子上。

**格子本身就是 button，所以用户说的「按键重叠」和「日期重叠」是同一件事。**

### 改法：按「天」分列，一周一行

不再把所有格子平铺成 14 列，改成**每天占一列**：

- **按天粒度**：每列 1 个格子，7 列 = 一周
- **按半天粒度**：每列 2 个格子（上=上午，下=下午），仍然 7 列 = 一周
- 日期标签放在**列顶**（不是格子顶），折行时不会压到上一行

这样：
- 320px 上每列约 36px，格子可点
- 折行不再有标签重叠
- 「一周一行」也符合人对日程的直觉

还要加的：
- **格子最小尺寸兜底**（`min-height`），避免极端情况下又变得太小
- **月份分隔**：跨月时在行首标出「10 月」「11 月」，不然 30 天以上找不到北

### 验收标准

在 320px / 390px 两个宽度下，用几何检测确认：
- 0 个标签压在其它格子上
- 0 对横向重叠的标签
- 每个格子 ≥ 32px
- 无横向溢出

## 二、首页 / 落地页 ✅ 已完成

**做法：** `/` 变成落地页，`/new` 保持是创建表单；`*` 兜底也回首页
（链接打错的人在那儿有「粘贴链接」入口还有救，丢进表单页就彻底卡住了）。

页面里的插图全部用 CSS 画，不用图片文件：任何屏幕密度下都清晰，
跟主界面共用同一套设计语言，也不增加首屏请求。只有「算出来长这样」那一节
用的是**真实截图**（`public/shots/results.jpg`，取自一个真跑过的示例活动，
假名字假地名）。

「朋友发我链接了」这个入口放在**第一屏**，没有埋到页尾 ——
设计文档 §4 说瓶颈是受邀者不是组织者，拿着链接来的人不该往下翻半天。
发过活动的人，分享区会自动换成带着他真实活动链接的文案。

**现状（改之前）：** 访问 `/` 直接跳到 `/new`（创建活动表单）。第一次来的人不知道这是干什么的。

### 落地页要有

1. **一句话说清是什么**
   「什么时候有空，想去哪里 —— 一起定」
2. **三步说明**（配小图）
   - 建个活动，把链接发群里
   - 大家点开涂自己的空闲时间、选想去的地方
   - 系统算出大家都能去的方案
3. **为什么不一样**（这是区别于 Doodle 的地方）
   用设计文档 §3.1 那个反例做成一张对照图：
   「去云南要 5 天、去露营只要 2 天 —— 时间和地点不能分开算」
4. **两个入口**
   - 主按钮：发起一个活动 → `/new`
   - 次入口：朋友发我链接了 → 一个输入框，粘贴链接直接跳过去
5. **分享到群里的那一段文案**（方便第一次用的人直接复制）

### 顺带

- `index.html` 的 OG 标签已有，落地页继承即可
- 底部放一句「免费、不用注册、不收集手机号」

## 三、预算改成具体金额

**现状：** 提名时选「省一点 / 一般 / 舍得花」三档，只能展示，没法算。

**改成：** 每个人对每个目的地**填一个整数金额**（元），然后算统计。

### 数据模型

`votes` 表加一列 `budget_amount INTEGER`（可空）：

| 字段 | 含义 |
|---|---|
| `level` | 想去(2) / 都行(1) / 不想去(0) —— 不变 |
| `budget_amount` | **我最多愿意为这趟花多少**（元，整数，选填） |

语义：绑在「我对这个目的地的态度」上，而不是单独一张表 ——
「我想去云南，愿意花 3000」是一句话，拆开没意义。

**选填**，不强制。强制填会让人卡住，而且填不准的数字比如实不填更糟。

### 展示

每个目的地显示：
- **中位数**（主）+ **平均**（辅）
- 范围：最低 ~ 最高
- 填了的人数：`3/6 人填了预算`
- 如果填的人太少（< 半数），标注「样本太少，参考意义有限」

**为什么中位数放主位**：一个人填 50000 就能把平均值拉飞，中位数不会。
这种「有人乱填」的场景下中位数更可靠。

### 界面上要讲清楚

「愿意花多少」和「这趟要花多少」是两回事。界面上要明确写：
**「你最多愿意为这趟花多少？」** —— 不是问目的地真实价格。

### 方案卡片上带出来

结果页的每个方案卡片，如果该目的地有预算数据，附一行：
`人均约 2000（中位数，5 人填）`

## 五、【插入】全量代码审查 + 修 bug

在做落地页之前，先把已提交的代码整个审了一遍：两个独立的审查员分别扫前端和
后端 + 核心算法，每一条我都自己重新验证过（不采信没跑过的结论）。

**这一轮抓到并修掉的，都是「界面看着正常、数据是错的」那一类。**

### 1. 按半天粒度时，「天数」被当成了「槽位数」（最严重）

`daysNeeded` 是**天数**（参与者填的是「大概要去几天」），
而 `feasibleWindows()` 吃的是**槽位数**。按天粒度下两者碰巧相等，
按半天粒度下差一倍 —— 于是「要 2 天」被算成 2 格＝1 天，而卡片上照写「2 天」。

修法是加 `slotsForDays()`，把换算收敛到一个地方。影响到：
`planner.ts`、`results.ts`、`admin-actions.ts`、`FinalPage.tsx`、`ShareCard.tsx`。

**证据**：修之前，一个只有一天半空闲的人被判成能去「要两天」的地方；
修之后正确地被排除。用例见 `tests/planner.test.ts` 的「按半天粒度」那组。

### 2. 热力图里「上午」从来没显示过

```ts
ts % 86400 === 0 ? ' 上午' : ' 下午'    // ← 永远是 false
```

`rangeStart` 是当天 00:00 减去 8 小时，所以任何一格的 `ts % 86400`
只会是 57600 或 14400，永远不等于 0。结果每一格都标「下午」。

同一个坑 `slots.ts` 里早就写了注释提醒（「不要用时间戳取模」），
热力图没跟上。改成按槽位序号的奇偶判断。

### 3. 意愿匿名只在界面上成立

「不想去」的人名只被界面藏了起来，数据整包照发 ——
谁都能按 F12 看到谁投了「不想去」，而这正是这个设置唯一要保护的东西。

改成服务端直接不发：活动详情要带自己的 token 才拿得到自己的票；
结果接口把 `missing` 里 `reason === 'unwilling'` 的条目**整条删掉**，
数量改由 `unwillingCount` 给出。`busy` 不删 —— 那是「没空」这个事实，
不是意见，而且组织者需要知道差的是谁。

**证据**：`npm run smoke` 第 18 组，8 条断言，外加一个「非匿名活动照常点名」
的对照组，防止把功能改没了。

### 4. 人少于 3 人时，目的地会被无声丢掉

原来有一条「少于 3 人就换成并排对照表」的捷径，它只看**第一个投票的人**
有没有可行窗口 —— 他没有就整个目的地作罢，哪怕后面的人都能去。
同一批人换个加入顺序，答案就不一样。

删掉了这条捷径（它是同一件事的第二份实现，而且只多出一个界面上根本不渲染的
`blockedReason`），统一走主路径。

### 5. 其余

| 问题 | 后果 | 处置 |
|---|---|---|
| 时间网格的 `aria-label` 用了这一行第一天的月份 | 跨月那行里 11/1 被念成「10月1日」 | 改成取格子自己的月份 |
| 网格的格子是 `<button>` 但没有 `onClick` | 只用键盘的人**填不了这张表** | 补上；用 `detail === 0` 区分键盘与鼠标，避免鼠标点一次走两步 |
| 日期格的 key 和「早/午」Fragment 的 key 撞了 | React 复用节点，控制台报警告 | 加前缀 |
| 定案的忙标记只按起始槽位做 key | 点一个，「同一时段的另一个目的地」也变「定案中」 | key 里带上目的地 id |
| 结果页空列表一律说「凑不出共同时间」 | 没勾选收集目的地时，这句话是假的 | 按三种成因分别给话术 |
| `slotCountFor` 静默封顶 180 | 建一年长的活动，界面只画到 6/29，两处都没提示 | 建活动时用 `rawSlotCount` 拦下来并报错 |
| 投票的删+插不是原子的 | 中途失败 → 票没了、时间还在，表现为「哪个地方都不想去」 | 合成一个 `db.batch`；顺带按目的地去重，避免撞主键 |
| `db.select().from(votes)` 不带 where | 每次开结果页都读全库的票 | 改成 `inArray` 按活动筛 |
| 改名可以绕过重名检查 | 群里出现两个同名的人 | 三处改名路径都查重 |
| 标题 / 名字 / 目的地名 / 天数 / 目的地个数 / 人数都没有上限 | 1MB 的标题、1e21 的天数都能存进去 | 各自加上限 |

### 6. 验证工具补进仓库

上一轮验证时间网格时用的几何检测脚本是临时写的，**没进仓库** ——
于是「重叠从 16 处降到 0」这个结论谁也复现不了，下次改动也没有东西能挡回归。

这次补上，全部可以重复跑：

```bash
npm run dev                              # 另开一个终端
node scripts/shoot.mjs <url> --out=.shots/x    # 按屏截图，原生分辨率
node scripts/check-grid.mjs /e/xxx/fill        # 几何 + 键盘/鼠标 + 控制台
npm run smoke                                  # 端到端，含匿名那 8 条
```

`check-grid.mjs` 里有一条是「无障碍标签的日期必须逐格递增」——
跨月时月份取错会让序列掉头往下，用单调性抓它比肉眼找快得多。

⚠️ **在 Git Bash 里传路由参数要加 `MSYS_NO_PATHCONV=1`**：

```bash
MSYS_NO_PATHCONV=1 node scripts/check-grid.mjs /e/xxxxxx/fill
```

不加的话 Git Bash 会把 `/e/xxxxxx/fill` 当成 Windows 路径转换掉
（变成 `E:/...`），报「Cannot navigate to invalid URL」。踩过一次。
